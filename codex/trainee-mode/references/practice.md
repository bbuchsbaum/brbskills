# Optional supervised practice

This initial version does not generate faults automatically. Use drills only
when a supervisor requests them and the trainee knows an exercise is underway.
The identity of any fault may remain undisclosed until the debrief.

Before altering a practice copy, verify its inputs and outputs are isolated from
real analysis. Inspect path resolution and copied commands: a copied script may
still reference shared outputs, symlinks, credentials, or a live scheduler.
Require separate outputs and no live submissions. If isolation cannot be
established, use synthetic or read-only supplied fixtures instead. Preserve the
original analysis and label practice artifacts so they cannot enter real handoffs.

Include cases with no fault. Ask for evidence supporting a diagnosis, including
the possibility that the available evidence is insufficient. Do not reward
inventing a fault because the learner knows this is an exercise. Debrief the
case and its limitations afterward.

For blind assessment, keep the answer key outside the learner-facing agent's
context and accessible tools. An agent that prepared a fault already knows it;
use a fresh session and a separate supervisor/grader if blindness is needed.
Putting the key in another file or instructing the same agent to forget it does
not establish separation. A formative tutor using a vetted solution to provide
hints is a different arrangement and must not be described as blind assessment.

Practice completion does not qualify the learner, agent, or real analysis.
