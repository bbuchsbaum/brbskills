# Report publish

reportbox is a self-hosted Cloudflare archive of static HTML reports. Each project has
an index at `/p/<project>/`, a `latest/` alias and immutable report versions. Reviewers
type the project password once (it is remembered for 30 days), or use a share link that
skips the password. Use this skill when someone other than the user must see a report.
For the user's own quick look at a remote report, use a local viewer such as `report-view`.

Requirements: the `reportbox` CLI (one stdlib Python 3.9+ file, `cli/reportbox.py` in the
reportbox repository), already configured on this machine with `reportbox setup` or
`REPORTBOX_URL`/`REPORTBOX_TOKEN`. Check with `reportbox ls`. If it is not configured,
stop and ask the user. Never ask for, print, or store the admin token yourself.

## Publish

```sh
reportbox ls                                   # projects; confirm the target exists
reportbox publish PATH --project P --title "..." [--notes "..."] [--source "..."]
```

- `PATH` is a report folder (with `index.html`, or exactly one `.html`) or an `.html` file.
  It may be `HOST:PATH` on any ssh host; single-quote remote variables, e.g.
  `'trillium:$SCRATCH/study/report'`. ssh never prompts, so if it fails, ask the user to
  authenticate in their own terminal.
- Point at a clean report folder, not a data directory. For neuromosaic, render into its
  own folder or stage one with `neuromosaic::write_report_bundle(report, dir)`. If the
  default `--max-mb 500` guard refuses the folder, fix the folder rather than raising the limit.
- Write a specific title (analysis, contrast, version) and short notes on what changed:
  they become the index entry reviewers scan. `--source` defaults to `host:path`; prefer a
  git SHA or job ID when you have one.
- Report the printed `report:` and `index:` URLs. Only unchanged files are deduplicated;
  every publish creates a new version, and earlier versions stay listed.

## Projects and access

Each project can combine four ways in. All end in a 30-day browser session for that
project only. Run `reportbox status` to see which ones the server has enabled.

| Method | Use when | Commands |
|---|---|---|
| Password | A lab group; "link + password" sharing | Generated by `project create` (printed **once**); `passwd P` replaces it |
| Share link | Quick access with no sign-in | `link create P --label "who" [--days N]`; `link list`; `link revoke P ID` |
| Google sign-in | Named people with Google or Workspace accounts | `member add P person@uni.edu` or `member add P @institution.org` |
| Emailed link | Named people with any address (if enabled) | Same member list |

**Choosing for a new project.** Default to a password project, which is the closest to
here.now. If the user names specific collaborators, add them as members instead of
sharing the password, so each person can be removed individually and appears in
`reportbox signins P`. For an institution-wide audience use `@domain`. Public mail domains
such as `@gmail.com` are refused, so add those people individually. Use
`project create P --no-password` when only named members and links should get in.

**Passwords.** The agent creates a password only when it creates a project the user asked
for. The CLI generates it; never invent or reuse one. Give it to the user once in the
conversation. Do not write it to files, commits, memory notes, Slack or email. It is stored
only as a hash, so a lost password means `reportbox passwd P`, which signs everyone out.

**Credentials of other people.** Never handle anyone's Google or email credentials. The agent
only edits the member list. Sign-in happens in the reviewer's own browser.

**Server setup is the user's job.** Google sign-in needs an OAuth client created in Google
Cloud Console and stored with the repository's `scripts/configure-google.sh`. Emailed links
need a sending domain. If `reportbox status` shows a method off, explain that; do not try
to configure secrets yourself.

Other maintenance: `reportbox signout P` signs everyone out; `reportbox rm ID` deletes a
version, and `reportbox gc` later reclaims its storage.

Adding or removing members, changing passwords, creating or revoking share links, and
deleting versions or projects all change who can see research results. Confirm them with
the user first, naming the project and the people affected.

## Announcing

When the user wants others notified, post the index or report URL to the agreed channel
(Slack, email). Members only need the URL; they sign in themselves. Never put a password
in the same message as the link; send it separately, or use members or a share link instead.

## Data rules

Reports go to a third-party host (Cloudflare), behind the project password. Publish only
reports the user intends to share, and never participant-identifiable data. Reports are
treated as trusted content: their JavaScript runs unsandboxed, so never publish HTML from
third parties.
